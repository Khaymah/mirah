## 3. Spike بـ Rust (قرار المالك: نبدأ الكود على طول من غير Phase 0)

- **اللي اتعمل:** binary بـ Rust (`spike`). بيشغّل أي أمر جوه pty، وبيقفل BDSM ويرجّعه، وبيقسّم السطر، ويعمل bidi وshaping (عربي وفارسي و"لا")، ويحوّل المؤشر لمكانه المرئي، ويرسم الصفوف اللي اتغيرت بس جوه mode 2026. بيرد على DSR 6n من الشاشة المنطقية، وبيمرر باقي أسئلة الترمنال (DA وXTVERSION وkitty وDECRQM وOSC 10/11) للترمنال الحقيقي. وبيمرر OSC 52 وعنوان النافذة.
- **الملفات:** `Cargo.toml` · `src/main.rs` · `src/bridge.rs` · `src/render.rs` · `src/segment.rs` · `src/shape.rs` · harness الاختبار في `research/e2e/`
- **التحقق:**
  - `cargo test`: 19 من 19 نجحوا. `cargo clippy`: مفيش warnings.
  - e2e على تطبيق Ink (نفس framework بتاع Claude Code وGemini): الإطارات سليمة، والعربي متوصّل ومترتب، و`>` و`●` فضلوا على الشمال، والشدة فضلت مع حرفها، والـ exit code صح.
  - vim: اشتغل بعد التصليح، ومعاه resize.
  - الأداء: 20 ألف سطر عدّوا في 0.19 ثانية (التشغيل المباشر 0.23). 200 frame كامل عدّوا في 2.07 ثانية زي التشغيل المباشر بالظبط.
  - **ماتجربش:** Claude Code وCodex الحقيقيين (مش متسجّل دخول)، وترمنال حقيقي بعين بني آدم.
- **اكتشافات:**
  1. Ink بيرسم مؤشر **وهمي** كخلية inverse، فتحويل مكان المؤشر الحقيقي مش كفاية. محتاجين قاعدة تنقل الخلية دي لمكان الكتابة المرئي (MVP).
  2. فيه تطبيقات بتعمل shaping بنفسها (vim، وmod الـ Claude Code لما يكون على `arabic=forms`). صلّحتها: أي presentation form بيرجع للحرف الأصلي ويتشكّل من جديد.
  3. في vim "لا" بتظهر حرفين متوصلين مش ligature. لسه مش عارف السبب.
  4. الأداة بتجمّع التحديثات، فبتبعت للترمنال أقل من ربع الـ bytes لما الـ output كبير.
- **الجاي:** اختبار يدوي في ترمنال حقيقي (GNOME Terminal وiTerm2 وKitty) مع Claude Code وCodex وهم متسجّلين دخول، وتصليح المؤشر الوهمي.
- **مفتوح:** اختيار الاسم (متأجل). المقابلات (Phase 0 · T0.1) لسه ماتعملتش.
