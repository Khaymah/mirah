# ADR 0001: لغة وstack الأداة

- **الحالة:** مقبول (2026-11-05، بعد المقارنة العملية في `Plan/Research/RustVsGo.md`)
- **التاريخ:** 2026-11-05

## السياق

الأداة بتشتغل في الـ terminal وسط المستخدم والـ agent. لازم تبقى binary واحد بيتسطّب بسهولة، والـ latency بتاعها مايتحسّش، وتفهم VT كامل وUAX#9 كامل. الـ stack الافتراضي للمالك (Bun · Hono · Drizzle · PostgreSQL · Next.js) معمول لتطبيقات الويب، ومفيش فيه حاجة تنفع هنا غير Bun.

## الخيارات

| الخيار | المميزات | العيوب |
|---|---|---|
| **Rust** + portable-pty + alacritty_terminal + unicode-bidi | binary واحد، أسرع حاجة، مكتبات VT وbidi ناضجة، ConPTY متاح بعدين | تطوير أبطأ في الأول، وعدد اللي يقدروا يساهموا أقل |
| Go + creack/pty + charmbracelet/x/vt + go-opentype/bidi | binary واحد، الكود أقصر بـ 37%، فيه بيانات التوصيل الرسمية من Unicode، ومساهمين أكتر | مكتبة الـ bidi الصحيحة عمرها 3 شهور ومحدش بيستخدمها، و`x/vt` لسه v0.1.0، وWindows محتاج مكتبة pty تانية، وصعب تتحط جوه ترمنالات أو تتعمل WASM |
| Bun/Node + node-pty + @xterm/headless + bidi-js | أسرع prototype، والمالك عارف الـ stack ده | محتاج runtime وnative addon، وهو نفس stack الـ agent-rtl فمفيش تميّز |

## الدليل العملي (2026-11-05)

القياس الكامل في `Plan/Research/RustVsGo.md`. باختصار:

- **الـ bidi:** مكتبة Rust نجحت 100% في الـ conformance الرسمي. مكتبة Go الرسمية نجحت 66.78% بس. go-opentype/bidi نجحت 100%، بس عمرها 3 شهور ومحدش بيستخدمها.
- **محاكي الترمنال:** المحاكيين طلّعوا نفس الشاشة في 3 جلسات، منهم Claude Code الحقيقي.
- **الأداء:** متساوي.
- **حجم الكود:** Go أقصر بـ 37%.

## القرار

**Rust.** ممكن نعمل prototype سريع بـ Bun في Phase 0 لو هيوفّر وقت في التجربة، بس الكود اللي هيتنشر هيبقى Rust.

## النتايج

- ✅ binary واحد بيتوزع على brew وcargo وGitHub Releases، ومش محتاج Node.
- ✅ الـ crate الأساسي (`segmenter + bidi + shaper + cell map`) ممكن يتنشر لوحده كمكتبة، وأي TUI أو ترمنال تاني يقدر يستخدمه. ده بيزوّد عدد اللي هيستفيدوا من المشروع.
- ⚠️ المساهمين لازم يعرفوا Rust. المساهمات في الـ corpus وجدول التوافق مش محتاجة كود.
- ↩️ **الرجوع في القرار:** لو اتعطلنا في Phase 0، نرجع لـ Bun prototype ونعيد التقييم.
