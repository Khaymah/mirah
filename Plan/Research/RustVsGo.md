# مقارنة عملية: Rust ضد Go

> التاريخ: 2026-11-05 · كل الأرقام دي اتقاست في الجلسة دي، والكود في `research/compare/`

## الخلاصة

قبل القياس كان Rust متقدم بفرق كبير. بعد القياس الفرق **ضاق**. فاضل لـ Rust ميزتين حقيقيتين: **نضج المكتبات** اللي بيعتمد عليها، و**إن المكتبة ممكن تتحط جوه ترمنالات تانية**. في المقابل، الكود في Go أقصر بـ 37%.

## 1. الـ bidi: ملف Unicode الرسمي (BidiCharacterTest 18.0، 91,707 حالة)

| المكتبة | الترتيب المرئي صح | المستويات صح | الوقت | الاستخدام الفعلي |
|---|---|---|---|---|
| Rust `unicode-bidi` 0.3.18 | **100%** | **100%** | 0.24s | 569 مليون تحميل |
| Go `go-opentype/bidi` v0.2.0 | **100%** | **100%** | 0.19s | ولا مشروع بيستخدمها · نازلة يوليو 2026 |
| Go `SCKelemen/unicode` v1.1.1 | 84.13% | 84.13% | 0.17s | الكود نفسه مكتوب فيه إن N0 (الأقواس) "not fully implemented" |
| Go `x/text/unicode/bidi` v0.43.0 | 66.78% | مش متاحة من برا | 0.48s | الرسمية، ومكتوب عليها "UNDER CONSTRUCTION" |

**ليه x/text فشلت:** `Order()` بترجّع الـ runs بالترتيب المنطقي، والـ levels مش متاحة من برا. الحالات اللي فشلت كلها أقواس وأرقام جنب حروف عربية، زي `ا(١)` و`a(1)`، ودي حاجات بتظهر كتير في output الـ agents. وفيها كمان bug في `RunAt()` و`Line()`.

## 2. محاكي الترمنال (VT): نفس الـ bytes على المحاكيين

| الجلسة | Rust `vt100` 0.18 | Go `charmbracelet/x/vt` v0.1.0 |
|---|---|---|
| تطبيق Ink فيه كتابة عربي | نفس الشاشة | نفس الشاشة |
| vim مع ملف عربي | نفس الشاشة | نفس الشاشة |
| **Claude Code v2.1.318** (شاشة البداية) | نفس الشاشة | نفس الشاشة |

النضج: `vt100` عليه 18 مليون تحميل. `x/vt` لسه v0.1.0 من أكتوبر 2026، بس وراه شركة Charm.

## 3. نفس الـ segmenter والـ shaper في اللغتين

| | Rust | Go |
|---|---|---|
| عدد السطور من غير الاختبارات | 398 (segment 197 + shape 201) | **249** (segment 160 + shape 89) |
| الاختبارات | 20 من 20 | 14 من 14، نجحوا من أول مرة |
| على corpus من 20 سطر صعب (جداول، روابط، عبري، فارسي، أقواس، "لا") | **مطابق 100%** | **مطابق 100%** |
| السرعة (100 ألف سطر) | 14.38 µs للسطر | 14.17 µs للسطر |

**ليه Go أقصر:** go-opentype فيها بيانات التوصيل الرسمية من Unicode (`ArabicShaping.txt`) وفيها انعكاس الأقواس، وفي Rust كتبت الاتنين بإيدي.

**اكتشاف:** المقارنة كشفت bug في الـ shaper بتاع Rust. لما الشدة بتيجي في خلية لوحدها كانت بتقطع التوصيل، ومكتبة Go كانت صح. **اتصلح**، واتضاف عليه اختبار.

## 4. Claude Code الحقيقي جوه الـ spike

الـ 24 صف بتوع شاشة البداية طلعوا مطابقين للتشغيل المباشر، والسهم لتحت حرّك الاختيار عادي.

## الجدول النهائي

| المعيار | الأحسن |
|---|---|
| صحة الـ bidi | تعادل (Rust وgo-opentype الاتنين 100%) |
| نضج المكتبات اللي بنعتمد عليها | **Rust** بفرق كبير |
| محاكي الترمنال | تعادل في النتايج، وRust أنضج |
| السرعة | تعادل |
| حجم الكود وسرعة الكتابة | **Go** (أقصر بـ 37%) |
| Windows ConPTY | **Rust** (API واحد في `portable-pty`) |
| تتحط جوه ترمنالات وWASM | **Rust** |
| عدد اللي يقدروا يساهموا | **Go** |

## المخاطرة لو اخترنا Go

مكتبة الـ bidi الوحيدة الصحيحة في Go عمرها 3 شهور ومحدش بيستخدمها. الحل: نعمل vendor ليها (رخصتها BSD-3)، ونحط اختبار الـ conformance في الـ CI.
